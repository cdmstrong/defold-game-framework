# 实施任务与验收

日期：2026-11-18。当前完成：规划、M0、M1、M2 与 M3。M0 的构建、运行和交互证据见 [验证记录](../verification/m0.md)，M1 的导航、弹窗与暂停证据见 [验证记录](../verification/m1.md)，M2 的组件、主题与四尺寸适配证据见 [验证记录](../verification/m2.md)，M3 的存档/迁移/设置/音频/本地化证据见 [验证记录](../verification/m3.md)。M4–M7 尚未开始。

## M0：可复现工程与构建入口

依赖：本规范。产物：UI Demo 空入口、版本清单生成脚本、build/test/bundle 命令说明。

1. 核对所有本地约束，保留既有平台跳跃资源；新建 `examples/ui_demo` 入口并设置项目启动资源。
2. 引入清单指定 Druid、Monarch、Event 提交，配置 `[library] include_dirs = framework`，检查第三方许可证。
3. 明确输入 action：touch、鼠标滚轮、返回、确认；按 Druid 版本配置，验证自动输入焦点不与页面管理冲突。
4. 配置匹配本机 1.14.1/SHA 的 Bob 和 Java；记录工具校验值。构建脚本按 shell 安全规则处理路径，失败返回非零。
5. 定义 `build`、`unit`、`integration`、`bundle-html5` 四个可重复入口。Bob resolve/build/bundle 的参数先依据该版本 help 确认，再写脚本。

验收：新环境可获取固定依赖；桌面构建成功；空 Demo 启动无资源错误；HTML5 包可由本地 HTTP 服务打开。归档命令、退出码、日志及引擎版本。此阶段通过才将 dependencies.json 标记为 integration_verified。

## M1：Core + 单一导航流程

依赖 M0。产物：app/event_bus/pause、UI Manager、Home/Components/Settings/Dialog 屏幕。

- 所有路由注册在主 Collection；首屏显示等待注册完成。
- Home → Components → Settings → 返回；打开和关闭模态弹窗。
- 建立 EventBus 生命周期和页面消息桥接；导航只经过 UI Manager/Monarch。

验收：连续 30 次进入/退出页面无残余订阅和重复点击；未知路由、连续点击、转场失败均能恢复；弹窗下层收不到点击；关闭一个暂停原因不解除其他暂停原因。纯 Lua 测试覆盖订阅移除、监听器异常和嵌套派发，集成测试覆盖真实 GUI 输入。

## M2：可复用 UI Demo

依赖 M1。产物：Button、ProgressBar、CurrencyBar、ItemCard、ConfirmDialog、Toast、Tab、Scroll；亮/暗两套主题。

- 每种控件展示正常、禁用、空内容或边界状态；所有资源在 framework 导出目录内。
- 主题使用真实九宫格资源；GUI 模板控制布局；屏幕比例变化时保持可操作区域。
- 加入中英文示例长文本，确定字体授权与字符覆盖。

验收：960×640、1280×720、1024×768、390×844 四种尺寸截图；控件不遮挡、无点击偏移；列表滚动与点击不冲突；切换主题不重建业务状态。截图附操作步骤，截图文件存在不自动视为通过。

## M3：本地状态与应用服务

依赖 M1；M2 提供演示界面。产物：Save/Migration、Settings、Audio、Localization。

验收：新档、旧档迁移、坏档、未来版本、写入失败各有结果；失败不覆盖可恢复旧档；更改音量/语言后重启恢复；中文无缺字；HTML5 首次交互后可播放音频；浏览器刷新后存档存在。双槽恢复测试用真实截断或无效数据，不只 mock 成功路径。

## M4：平台与广告抽象

依赖 M3。产物：browser/desktop 基础 adapter、mock/unsupported 广告 adapter、Analytics 日志 adapter。

验收：广告完成只奖励一次；取消、不支持、错误不奖励；重复回调、超时、并发请求和退出页面不导致重复奖励或操作已销毁 GUI；广告期间暂停/静音正确恢复；生产配置不能意外启用 Mock 成功奖励。

普通浏览器验证只代表普通 H5 页面。真实聚合平台和移动 SDK 另列接入任务与平台专属验收。

## M5：独立消费与 Framework 0.1 发布候选

依赖 M0–M4。产物：Library ZIP、第二个独立消费工程、接入说明、CHANGELOG、框架 API 文档。

验收：消费工程只通过库依赖获得 framework；无源码复制、无外部资源漏引用；可构建、显示组件、存档和运行模拟广告；固定提交可复现；升级/回滚演示记录依赖版本。记录导出目录、许可证、HTML5 包大小、启动时间和 GUI 节点数，先建立实测基线再设性能阈值。

版本 0.1 可用于首个产品实验；完成约定 V1 能力及消费者回归后才发 1.0。远程发布和正式商店提交是独立交付步骤，不因本地打包成功就标记上线。

## M6：经营模块与首个真实循环

依赖 M5。创建 defold-modules，首先 Economy、Inventory、Upgrade，再 Production、Offline。以一个维修工作台为示例：消耗零件 → 等待维修 → 获取收入 → 升级工作台 → 保存 → 重启/离线领取。

验收：不足余额/零件不改变 state；升级成本与收益可配置；离线收益上限和重复领取被控制；同一流程 UI 操作与纯 Lua 测试一致。Controller 负责事务，模块不引用 GUI、msg 或第三方 SDK。

## M7：经营模板与产品化

依赖 M6。将已验证循环整理为 template-tycoon；复制出独立手机维修或超市游戏。模板提供游戏名称、包标识、依赖清单、配置、资产和测试说明。

验收：复制后改配置即可运行；模板修改不影响已生成工程；完成一款真实游戏的首次游玩、成长、保存和再次进入闭环。接入选定 H5 平台并验证平台生命周期/广告，之后分别安排 Android 和 iOS 构建、签名与真机检查。Arcade/Puzzle 模板在该流程验证后再排期。

## AI 每项任务的执行协议

1. 读取架构、当前版本清单、目标任务和相关源码。
2. 只实现当前验收需要的功能；公共库能力优先复用。
3. 业务修改跑对应纯 Lua 测试；资源/GUI 修改需引擎构建和交互验证。
4. 留下命令、退出码、日志、截图与未通过项；检查结果后再进入下一依赖阶段。
5. 不把模拟广告当作平台接入，不把桌面成功当作 H5/移动验证，不把构建成功当作玩法完成。

后续创建 AGENTS.md 时引用本规范，避免复制多套冲突规则。暂不创建定时任务或自动发布流程。

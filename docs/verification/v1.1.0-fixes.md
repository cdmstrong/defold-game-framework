# v1.1.0 修复验证记录：广告异步 / 存档错误语义 / 槽位分组 / 导航超时

日期：2026-11-18。本轮为可用性修复，不新增模块。

## 修复 1：真实广告异步链路闭合（provider 契约 V2）

**问题**：provider 的 `show_rewarded` 在注册 JS 完成回调后立即同步读取结果。真实广告从
`show()` 到 `onClose` 间隔数秒到数十秒，同步读必然拿到空结果 → 提前返回失败、恢复游戏；
晚到的 JS 结果还会污染下一次请求。

**方案**（见 `framework/platform/provider_contract.lua`）：
- `show_rewarded` 只发起播放，返回 `{ pending = true }`；终态由门面每帧 `update()` 轮询
  `provider:poll(request_id)` 获取。
- JS 结果协议带 `request_id`（`window.__ad_result__ = { request_id, ... }`，
  发起时 `window.__ad_active__ = request_id`）。`poll` 只消费 request_id 匹配的结果，
  不匹配的（stale，晚到的旧请求结果）直接丢弃并清理，绝不返回。
- 看门狗移到门面 `update()`：pending 超过 `timeout_ms + grace` 兜底结算为
  `timeout` 并释放 busy / 暂停，杜绝广告卡死导致游戏永久暂停。
- leyuan（233）的 SDK 加载（script onload）同样是异步的：`init()` 只注入 script 标签，
  SDK 就绪由每帧 `poll_init()` 检查 `window.MetaH5Ad`；`is_supported` 未就绪返回 false
  且不缓存，就绪后自然变 true。show 前未就绪直接拒绝（`sdk_not_ready`）。
- mock provider 新增 `config.async` 模式（pending + poll + 延迟结算），纯 Lua 测试
  得以驱动完整轮询/超时链路（此前阻塞式 mock 同步返回，超时路径无法测试）。

**关键 bug**（单测抓到）：provider 在丢弃 stale 结果时误清 `active_request`，导致当前
请求永远无法再 poll。已修复：stale 丢弃保留 active_request。

## 修复 2：存档「读取失败」不再被当成首次运行

**问题**：`storage.defold.read` 把 pcall 失败（IO 异常）与文件不存在都返回 `(nil, nil)`；
`save_manager.read_best` 在两槽皆 nil 时直接返回默认值。后续保存会用默认数据覆盖真实存档。

**方案**：
- storage.read 语义明确三分：`(nil, nil)`=不存在；`(nil, err)`=读取失败（read_failed/corrupt）；
  `(envelope, nil)`=成功。
- `read_best`：两槽皆 nil 时若任一槽有硬错误 → 上报错误而非默认值；一槽失败一槽健康 →
  健康槽优先。
- **commit 保护**：`commit(slot)` 在 `load(slot)` 成功前一律拒绝（`not_loaded`），
  即使业务忽略 load 的错误直接存档，框架层也拒绝写入，原存档不可能被默认值覆盖。
  提供 `mark_loaded(slot)` 供明确要新建档的场景。

## 修复 3：槽位接口与实现对齐（slot 真分组）

**问题**：`load(slot)` / `commit(slot, ...)` 接受槽名但实际始终读写同一组 primary/backup，
两个逻辑存档共用实例会互相覆盖。

**方案**：slot = 逻辑存档名（"game" / "settings" / 默认 "default"），每个逻辑 slot 拥有
独立的物理键对 `<slot>_primary` / `<slot>_backup`；revision / cache / loaded 状态按 slot
隔离。一个 SaveManager 实例可安全管理多份独立存档。

## 修复 4：导航转场超时恢复

**问题**：`ui_manager.begin` 依赖 adapter 的 finish 回调复位 pending；回调丢失（popup 被
外部关闭、Monarch 内部异常）会让 `is_busy` 永久为 true，所有导航被拒绝。

**方案**：`ui_manager.update(now)` 每帧检查 pending 是否超过 `transition_timeout_ms`
（默认 10s，可配，now 可注入），超时按 `transition_timeout` 结算并释放 busy；dialog
场景经 end_modal 连带释放 pause。同时把 `adapter:update()` 移入 ui_manager.update，
由 app:update 统一驱动。

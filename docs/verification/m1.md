# M1 验证记录

日期：2026-11-18（Asia/Shanghai）。环境：本机 macOS / Apple Silicon，Defold 与 Bob 1.14.1，engine SHA `ee283d4dad9fa451dd6399d83602e1dc25133681`。

M1 边界：Monarch 是唯一导航栈；框架负责路由检查、转场期间拒绝重复请求、回调与清理；事件总线只通知数据变化、GUI 在自己的消息处理中更新节点；暂停按原因计数，关闭弹窗不会误解除其他暂停状态。

## 产物

- `framework/core/app.lua` — 应用生命周期（create/start/update/shutdown），服务逆序关闭。
- `framework/core/event_bus.lua` — 事件总线，订阅返回取消函数，嵌套派发用队列 + 快照，监听器异常隔离，派发上限保护。
- `framework/core/pause.lua` — 按原因计数暂停，`acquire(reason)` 返回幂等 release，多原因互不干扰。
- `framework/ui/ui_manager.lua` — 导航唯一入口，路由检查、转场去重、模态弹窗、回调与清理。
- `framework/ui/adapters/monarch.lua` — 把 Monarch 包装为 UI Manager 的导航适配器，暴露 top/has_history/is_busy/show/back。
- `framework/ui/screen.lua` — 单屏 Druid + Monarch 转场封装，统一 init/update/on_message/dispose。
- `examples/ui_demo/` — Home / Components / Settings / Dialog 四屏，真实 GUI 输入与按钮。

## 修复

- `framework/ui/screen.lua` 的 `dispose` 原调用 `monarch.on_transition(hash(id), nil)`，但 Monarch 在转场退出时已 `unregister` 该 screen，`on_transition` 内部 `assert(screens[id])` 在 `final` 阶段报 `There is no screen registered`。改为 `pcall` 防御性清除转场回调（screen 注销后回调已随记录销毁，无需强制清理）。

## 界限

- 转场动画固定 0.12s，30 次循环 + 自测步骤在桌面运行约 3–4 分钟；`integration` 的 M1 路径超时设 300s。
- 未验证 HTML5 多页转场与触摸输入（M2 覆盖屏幕适配与多尺寸截图）。
- 未验证 iOS、Android、真实广告平台。
- 自测通过真实桌面引擎运行 + GUI 输入断言，非仅源码静态检查。
